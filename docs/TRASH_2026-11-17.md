# Undo Delete and Trash

## Scope and privacy

Explicit individual deletions in History and Templates move to persistent Trash.
The inline Undo action (Command-Z outside editable text) restores the last deletion
in the current section. Dismissing Undo does not erase the trashed item. Trash is
opened with a labeled toolbar button, restores clips/templates individually and
confirms permanent deletion or Empty Trash. It loads 100 rows per section, with
an explicit Show More action. Restore never evicts an active item to make room.
Duplicate active content is kept unchanged; its Trash copy remains until cleanup
or explicit deletion. A clip outside History's current age limit cannot be restored
until that setting is changed. Pins/favorites and original timestamps survive.

Trash retention defaults to 7 days; 30 days is optional. Changing 30 to 7 requires
confirmation that older Trash is removed immediately. Cleanup uses deletion time,
not original capture time, and runs at startup and approximately once per minute
while the app runs. It also runs on opening Trash and before restore. No background
daemon guarantees deletion while CopyStory is quit or the Mac sleeps.

History age expiration and capacity eviction bypass Trash. Clear History is an
explicit permanent privacy wipe: it removes matching active AND trashed clips,
respecting include-pinned choice, but does not erase Templates or template Trash.
Trash remains local plaintext with the store's owner-only protections; no new
network, clipboard, permission, login or Direct Paste behavior is introduced.
Trash can use additional disk space beyond the active History cap. The Preferences
storage display includes active History plus clip Trash. Permanent deletion does
not guarantee forensic secure erasure or remove external backups.

## Persistence / rollback

Both SQLite stores migrate version 1 to version 2 transactionally by adding Trash
tables/indexes. Original active rows are preserved. Images remain in the same
image directory and startup reconciliation recognizes both active and trashed
references. Move/restore are atomic database transactions; interrupted removal of
image files is reconciled at next startup. Unsupported schema versions fail closed.

Build 23 must not open a migrated store: its version gate rejects version 2, which
prevents its old image reconciler from deleting retained Trash images. Before any
real-data beta launch, back up both stores with CopyStory fully quit and verify the
backup. Rollback requires the matching pre-migration backup (losing changes made
after that backup), or continuing forward with a compatible build. Do not reset or
downgrade the schema flag. No live stores were used for implementation tests.

## Verification / remaining gates

Offline synthetic tests cover persistence/reopen, images, original metadata,
duplicates, restore capacity blocks, expiry boundaries, pinned clear behavior,
schema upgrade/unsupported versions/transaction rollback, model Undo, template
write draining and bounded pagination. Independent static review addressed three
findings: pending-template write races, unbounded listing, unavailable Templates.
Final test/build totals are reported separately with the exact validation run.

Still requires an isolated UI preview: Trash sheet layout, keyboard/VoiceOver,
confirm/cancel permanent deletion and 30→7 choices, Undo in both sections, reopen
recovery, duplicate clicks and return to the prior filters/selection. No live app
launch, installation, actual clipboard/paste, merge or upload is implied by these
offline checks. Real-data migration and Direct Paste require separate beta checks.

## Pre-beta migration checklist (plan, not executed)

1. Finish isolated UI testing using synthetic history/templates. Do not use the
   real store as a test fixture or launch the unsigned bundle above.
2. With the owner ready, quit the installed CopyStory cleanly. Verify the process
   stopped and the store lock is not held before copying; never copy mid-write.
3. Resolve the installed sandbox's actual Application Support/CopyStory directory
   from the app identity, not an old development directory. Preserve the complete
   directory (history.sqlite, Images, Library/library.sqlite and any journal files)
   in an owner-only local timestamped backup outside the live container. Preserve
   the installed build/version and preferences separately for rollback context.
4. Verify copy integrity with a recursive file-size/hash manifest without logging
   payload content. Validate both copied SQLite files read-only with quick_check
   and schema version. Stop on failure; do not migrate the live original.
5. Test migration on a SECOND disposable copy if needed, never on the sole verified
   backup. Confirm active record/image integrity and version 2 for both stores.
6. Only then install/launch the signed authorized beta. Verify recovery behavior
   and normal capture/Direct Paste with the owner's controlled walkthrough.
7. If rollback is needed, quit first and preserve the complete post-migration
   directory separately; do not delete it. Explain that Build 23 can only use the
   pre-migration snapshot and cannot see newer captures/templates. Restore via a
   reviewed reversible directory swap, not by changing PRAGMA user_version.

The verified backup contains sensitive clipboard history. Keep it local, owner-only
and out of git, cloud deliverables, logs, support screenshots and Library uploads.
Its eventual deletion is a separate owner decision; automatic Trash cleanup does
not erase backup copies.
