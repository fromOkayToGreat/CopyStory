## Clipboard and admission ordering

Real writer closure exists only in AppModel's default native environment, behind the platform barrier; it reuses ClipboardMonitor.write and exact own-write version. The adapter never reads legacy/private history or decodes current clipboard content. Its shared policy validates captured identity/age/permission/modifiers before one write, freezes successful version, then marks pending. History replay never re-admits; Library successful write enqueues the existing synthetic-or-real save immediately before any hide/restore/observer callback or await. Eligibility/demo/pause/lock/exclusion/retention/capacity and save/clear sequencing remain in existing code. Failed write/cancel-before-write admits nothing; already admitted storage survives later cancellation. Stale tasks cannot clear newer form/busy/feedback; admission warnings retain priority across final wait.
