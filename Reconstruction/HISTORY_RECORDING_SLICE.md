# Approved offline History recording slice

Approval: owner Sentinel_b3b498ddc1ec819187cb397518db5cbb, relayed by supervisor. Implements the bounded model from NEXT_HISTORY_SLICE_SPEC.md; does not authorize live integration or change FRO22 criteria.

New CopyStoryCore/HistoryRequestSimulation.swift supplies injected value snapshots and a final concrete in-memory HistoryRecordingSinks. Payloads are synthetic text or opaque image bytes; no real clipboard/store/event API, file/content logging, OS queries or UI wiring. Production PasteCoordinator/AutomaticPastePolicy and hard main-entry launch gate remain unchanged and disabled. No Library model/views/lifecycle changed. The Xcode generator only adds the new Core source to the existing target; no dependency/framework/target added.

An explicit modeled Paste consumes one attempt before sampling dependencies. Invalid/own/missing identity, cancellation, nonfinite/expired clock, dead/changed identity, denied/unknown permission or held modifiers reject before write. Passive selection/search/edit do nothing when idle and cancel pending work conservatively. Copy is separate and can be explicitly chosen after failed Paste; it records only a simulated write and can never schedule an event pair or actual history mutation. Repeated explicit Copy is not an automatic retry. No retry loop exists.

A successful simulated Paste write records exactly one admission *opportunity* and dismissal intention before pending completion. This is a sequencing hook, not insertion into actual History or an assertion that an already-stored History item should be duplicated. Capture eligibility, deduplication, pause/exclusions/retention/clear ordering and failed storage-write behavior remain actual-integration concerns. Failed simulated writes record no admission/dismissal/pair. Payload size/type/storage validation is not reimplemented here; image bytes remain opaque.

Final finish claims once before resampling. It freezes the captured identity/PID for a concrete down/up recording pair. It rechecks generation, sticky cancellation, clock/expiry, live/same identity, board version, permission and modifiers. Reentrant/stale snapshot callbacks cannot write twice, consume/clear a new pending request or overwrite its feedback. All feedback says simulation/blocked/unconfirmed; it does not claim actual Copy, posting or insertion. Identity values are supplied simulation data, not authenticated OS observations.

The stale-snapshot characterization deliberately records intent when the provider returns an old safe snapshot despite external test state changing. This is NOT a permission-loss acceptance pass or atomicity guarantee. No real source posting occurs anywhere in this slice. FRO22 effective-loss/zero-posting/fallback/restoration acceptance remains open; no supported stale-permission detector has been established. Protected/native input, actual focus/Space delivery, real clipboard and Library lifecycle remain outside scope.

Focused tests exercise passive/Copy separation; exact Unicode/image recording; duplicate/no-retry handling; all cancellation reasons before writes and pending selection/away-return; prewrite/final failures; one claim; same-PID different launch/path/bundle; late completion/cancellation; dependency reentry before write and final completion; explicit Copy after denied Paste; nonfinite clock/incomplete identity; stale snapshot characterization. Run these plus the relevant surviving Core and disabled-policy suites only. No GUI, clipboard or permission tests.

Build/snapshot protocol: commit coherent new model/tests/project inputs; export exact commit for dependency-free tests with explicit Xcode toolchain; unsigned compile-only archive and static no-event/no-AX checks; preserve new layer diff, source hashes, complete archive and verified Git bundle in a new durable checkpoint. Keep prior evidence immutable. No production signing, app launch, installation, build allocation or release action.
